# v1.3.3

## 🚀 优化与提速

### OCR 选车提速 + 三阶段点击 fallback（PR #29，@hui-shao）

- **搜索层提速**：每步固定连按 5 次 ↓ 后做 1 次 OCR，OCR 频率从 1/1 降到 1/5（向下搜索安全：目标只能从屏底进入，跳 5 步后屏底进入 5 行新内容）；卡底判定完整保留（像素差 3 次无变化 + OCR 文本相似 2 次 + 循环检测）
- **命中层修复**：点击坐标改为复选框中心 `(rx1+rx2)/2`，修复原 panel 水平中心点击距离复选框约 230px 导致勾选失败的问题；改为 SendMessage 单次后台点击 + hold=0.12 延长按压，避免复选框反复 toggle
- **三阶段 fallback**：① 鼠标后台点击 + 多次采样稳定判定（最快路径）→ ② 盲 Enter 兜底（失败回滚）→ ③ 键盘移动高亮 + Enter + 校正扫描（最稳路径保留）
- **实测提速**：列表 50 行、目标在 35 行时，约 14s → 6s（约 2~3 倍）

## 🔧 修复

### 后台车辆专精加点与全局恢复稳定性（PR #28，@AriaSulT）

- **专精加点重构**：归一化 ROI 检测技能树右上最终节点完成状态（粉色占比 ≥0.15）；加点弹窗状态机（弹窗头部 lime 占比 ≥0.25 + 文本判定）；「车辆已满专精」锁定弹窗检测与自动关闭；弹窗关闭等待（2.5s）；光标归位（Down×6 + Left×6）与本地重试
- **后台输入稳定化**：检测到用户按 Alt/Win 切窗时暂停按键投递（0.15s 稳定等待 + 20ms 轮询），避免游戏失焦时把技能树两步操作拆开导致加错点或流程中断
- 新增 481 行回归测试覆盖上述路径

### 筛选三阶段 fallback：阶段 3 预检修复

- 阶段 3 按 Enter 前预检复选框状态：已勾选直接返回 True，避免第三次 toggle 导致筛选静默失效（慢机器采样漏判 + 阶段 2 双 Enter 翻转场景）
- 卡底 / 循环 / 命中时补 `_save_filter_debug` 调试截图
- 清理死代码：删除 `_search_and_focus` 与 `enter_first=True` 死分支

### 升级与调校等待硬上限 60s → 90s

- 测试机加载慢时 61s 硬上限不够，`_wait_for_uandt_ready` 硬上限改为 `max(90, timeout+45)`；交互超时（16s 按 Esc 自动续期）与慢速 Esc 间隔（3s）不变

### 超抽选车：YOLO 等级标签二次校验误杀真目标

- 现象：超抽流程中 YOLO 已识别目标车辆（车型分类 conf 0.89+、NEW 角标交叉验证 conf 0.95+ 均通过），但等级标签 conf 波动至 0.34 时，二次校验硬门槛（0.50）不通过，降级模板匹配（classS2829.png）同样失败，最终拒绝上车，本批超抽直接结束
- 原因：
  1. v1.3.1 将 YOLO 等级标签硬门槛定为 0.50，但该类实测 conf 波动范围 0.3~0.9，真目标标签可低至 0.34，0.50 门槛按高值设定导致误杀
  2. 门槛不过时降级的模板匹配兜底：模板 classS2829.png 截自左上角「选中车辆信息卡」，与车卡网格上的等级标签样式（边框/背景）不一致，网格区域匹配得分天然低于 0.72 阈值，兜底形同虚设且进一步误杀
- 修复：YOLO 分支等级标签硬门槛 0.50 → 0.30（与 NEW 角标交叉验证阈值 tag_conf_floor 一致）；YOLO 判定通过后不再触发冗余模板匹配
- 验证：真实截图复现确认，真目标标签 conf 0.64~0.83 正常关联，波动低值 0.34 亦可过硬校验；模板匹配仅保留给 YOLO 完全未检出等级标签（cls_conf=0）的场景
